# راه‌اندازی روی سرور

سه فایل، یک دستور.

## نصب روی سرور خام

```bash
ssh root@YOUR_SERVER

apt-get update && apt-get install -y git
git clone -b feat/multi-tenant-foundation https://github.com/shootingv818/Makemyno.git /opt/makemyno
bash /opt/makemyno/deploy/install.sh
```

اسکریپت این کارها را می‌کند و بین هر مرحله بررسی می‌کند:

1. بسته‌های سیستم (پایتون، هدرهای Pillow، git، sqlite)
2. منطقه‌ی زمانی روی `Asia/Tehran`
3. محیط مجازی + نصب `requirements.txt`
4. **تست ایمپورت واقعی** همه‌ی کتابخانه‌ها — نه فقط «pip موفق بود»
5. ساخت `.env` از `env.template` و تولید کلید رمزنگاری (`WORKER_SECRET`)
6. **بررسی کامل بودن تنظیمات** قبل از تحویل به systemd
7. نصب دو سرویس systemd و روشن کردنشان

قابل اجرای مجدد است: بار دوم فقط کد و کتابخانه‌ها را تازه می‌کند و `.env` را دست نمی‌زند.

## بعد از نصب

```bash
bash /opt/makemyno/deploy/makemyno.sh check
```

این دستور واقعاً به تلگرام وصل می‌شود، هر دو توکن را باز می‌کند و **یک پیام تست به گروه لاگ می‌فرستد**. اگر ربات‌ها عضو گروه نباشند، همین‌جا می‌فهمی — نه دو روز بعد که تعجب کنی چرا گروه لاگ خالی است.

## دستورات روزانه

```bash
bash /opt/makemyno/deploy/makemyno.sh status    # سرویس‌ها، دیتابیس، سشن‌ها، خطاهای ۱ ساعت اخیر
bash /opt/makemyno/deploy/makemyno.sh logs      # لاگ زنده‌ی هر دو ربات با هم
bash /opt/makemyno/deploy/makemyno.sh restart
bash /opt/makemyno/deploy/makemyno.sh update    # git pull + تست ایمپورت + ری‌استارت
```

`update` قبل از ری‌استارت بررسی می‌کند کد جدید ایمپورت می‌شود یا نه. اگر نشود، **ری‌استارت نمی‌کند** و نسخه‌ی قبلی همچنان بالا می‌ماند. خطای نحوی که اینجا پیدا شود پنج ثانیه دردسر است؛ همان خطا اگر systemd پیدایش کند، یک سرویس بالا-پایین‌شونده است که خطای اصلی را زیر انبوه لاگ گم می‌کند.

## دو کار دستی که اسکریپت نمی‌تواند بکند

**۱. هر دو ربات را به گروه لاگ اضافه کن** و اجازه‌ی ارسال بده. `makemyno.sh check` تأییدش می‌کند.

**۲. یک نسخه از `WORKER_SECRET` جای امن نگه دار.** این کلید بکاپ‌ها، رمز ورکرها و توکن‌های سشن را رمز می‌کند. اگر سرور بسوزد و کلید را نداشته باشی، بکاپ‌های قبلی **هیچ‌وقت** باز نمی‌شوند.

```bash
grep WORKER_SECRET /opt/makemyno/.env
```

## ورکرها

ورکرها را دستی نصب نمی‌کنی — از پنل مالک، بخش «🛠 ورکرها»، با SSH و Docker خودکار راه‌اندازی می‌شوند. `GIT_REPO_URL` در `.env` باید به همین مخزن اشاره کند؛ اگر به مخزن قدیمی‌تری اشاره کند، «به‌روزرسانی همه‌ی ورکرها» بی‌صدا کل ناوگان را عقب می‌برد.

ماشین master خودش هم به‌طور پیش‌فرض کار ارسال انجام می‌دهد (`MASTER_AS_WORKER=true`).

## عیب‌یابی

**سرویس بالا نمی‌آید**

```bash
journalctl -u makemyno-owner -n 50 --no-pager
```

اگر `تنظیمات ناقص است (.env)` دیدی، یعنی یک کلید لازم خالی است — `makemyno.sh check` می‌گوید کدام.

**ربات جواب نمی‌دهد ولی سرویس بالاست**

`OWNER_ID` را چک کن. ربات مالک به هر کسی جز آن آیدی **هیچ** جوابی نمی‌دهد — این عمدی است، نه باگ.

**گروه لاگ خالی است**

ربات‌ها عضو گروه نیستند یا اجازه‌ی ارسال ندارند. `makemyno.sh check` قطعی می‌گوید.

## یک هشدار فنی جدی: `API_ID=2040`

آن `API_ID=2040` / `API_HASH=b18441a1...` که دادی، **اعتبارنامه‌ی عمومی و لو‌رفته‌ی Telegram Desktop** است. سال‌ها در اینترنت پخش شده و تلگرام می‌شناسدش.

برای **ربات** مهم نیست. مشکل جای دیگری است: بخش تلگرام این پروژه **اکانت‌های کاربری واقعی** مشتری‌ها را با همین اعتبارنامه لاگین می‌کند، و تلگرام اکانت‌هایی که با اعتبارنامه‌های لو‌رفته احراز می‌شوند را پرچم‌گذاری و بن می‌کند. یعنی با این تنظیم، شانس بن‌شدن اکانت مشتری‌هایت **به‌طور محسوسی بالاتر** است — و این دقیقاً چیزی است که مشتری بابتش پول داده.

مال خودت را بگیر، ده دقیقه کار است:

1. برو `my.telegram.org` → **API development tools**
2. یک اپ بساز
3. `API_ID` و `API_HASH` را در `.env` بگذار
4. `bash deploy/makemyno.sh restart`

اکانت‌هایی که **قبلاً** لاگین شده‌اند سشن‌شان سالم می‌ماند؛ فقط لاگین‌های بعدی از اعتبارنامه‌ی جدید استفاده می‌کنند.

## و یک نکته‌ی امنیتی

توکن‌ها را در چت فرستادی. اگر این گفتگو جایی به اشتراک گذاشته شود، هر کسی که ببیندش کنترل کامل هر دو ربات را دارد. عوض‌کردنشان در BotFather با `/revoke` سی ثانیه است — بعدش `.env` را به‌روز کن و `restart` بزن.
